# Development

## Requirements

- macOS 26 or later, Xcode 26 or later (Swift 6.2 toolchain)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)
- For live AI tests: `claude` and/or `codex` installed and logged in

## Layout

```
Package.swift            Swift package: AaronCore, AaronPreview, AaronAI, AaronPelican
Sources/, Tests/         package code and unit tests (Swift Testing)
App/project.yml          XcodeGen spec for the app and its test targets
App/Sources/Aaron        SwiftUI/AppKit application
App/Tests                hosted app unit tests (XCTest)
App/UITests              UI tests (XCUITest) and fixture scripts
App/SmokeTests           permission-free end-to-end scenarios
scripts/smoke-test.sh    runs the smoke scenarios
docs/                    user and developer documentation
```

See [design.md](design.md) for the architecture and
[../decisions.md](../decisions.md) for the reasoning behind choices.

The generated `App/Aaron.xcodeproj` and everything under `build/` are not
committed. `App/Sources/Aaron/Info.plist` is generated by XcodeGen from
`project.yml` but is committed so the source tree is complete; edit
`project.yml`, not the plist.

## Building

```sh
cd App
xcodegen generate
xcodebuild -project Aaron.xcodeproj -scheme Aaron -derivedDataPath ../build/DerivedData build
open ../build/DerivedData/Build/Products/Debug/Aaron.app
```

Or open `App/Aaron.xcodeproj` in Xcode after `xcodegen generate`. Rerun
XcodeGen whenever files are added or removed in the app targets.

Warnings are errors (`SWIFT_TREAT_WARNINGS_AS_ERRORS`). The line
`appintentsmetadataprocessor … warning: Metadata extraction skipped, no
AppIntents.framework dependency found` is a log message of an Xcode build
tool, not a compiler warning; there is no setting to silence it.

To run with a separate configuration (recommended while developing):

```sh
AARON_CONFIG_PATH=/tmp/aaron-dev.json \
  ../build/DerivedData/Build/Products/Debug/Aaron.app/Contents/MacOS/Aaron some.md
```

Files given as arguments are opened as documents.

## Testing

All features are developed test-first. The levels, fastest first:

| Level | Command | Needs |
|---|---|---|
| Package unit tests | `swift test` | nothing |
| App unit tests | `xcodebuild … test -only-testing:AaronTests` | nothing |
| Smoke tests | `scripts/smoke-test.sh` | nothing |
| UI tests | `xcodebuild … test -only-testing:AaronUITests` | UI automation permission |
| Live AI tests | `AARON_LIVE_AI=1 swift test --filter LiveProviderTests` | `claude`, `codex`, network |

A change is done when the first three are green with no warnings (and
the UI tests where automation is available), and the feature has been
tried in the running app. Details in [testing.md](testing.md).

## Conventions

- Logic goes in the package, where it can be unit tested without AppKit; the
  app target stays a thin layer of views and glue.
- Ranges into document text are `NSRange` in UTF-16 units everywhere,
  matching `NSTextView`.
- Every configurable value has a default and decodes leniently (missing keys
  use defaults), so hand-written configuration files stay short.
- User-visible features and behaviour are documented in `docs/user` in the
  same change.
- Commit messages: a summary line, a blank line, and a body explaining what
  and why.
