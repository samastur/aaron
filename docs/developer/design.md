# Aaron — design

Aaron is a native macOS (26+) Markdown editor aimed at writing blog posts,
with first-class (but optional) support for Pelican sites. This document
describes the architecture. The reasoning behind individual choices is in
[decisions.md](../decisions.md).

## Goals

- Write and edit Markdown files in a native, fast editor.
- Show a live preview in a side panel, rendered either by the built-in
  Markdown renderer or by user-configured external tools (for example a
  Pelican renderer that produces the page exactly as the site would).
- A separate *review mode* in which AI actions (grammar, fact checking,
  style, …) produce suggestions that are highlighted in the text and can be
  accepted or dismissed one by one. Nothing is changed without the author
  accepting it.
- User-defined AI actions, each with its own prompt and AI provider.
  Providers are command-line tools (`claude -p`, `codex exec`) so existing
  subscriptions are used; no API keys are stored by the app.
- Pelican awareness: metadata header handling and tag autocompletion on the
  `Tags:` line, with tags supplied by a configurable command.
- No knowledge of where content or tools live is compiled in. Every path
  and command is configuration.

## Non-goals (first version)

- WYSIWYG editing, rich text, or multiple Markdown flavours.
- Scroll synchronisation between editor and preview.
- Persisting AI suggestions between sessions.
- Calling AI HTTP APIs directly.
- Sandboxing/App Store distribution (external tools require an unsandboxed
  app).

## Module layout

```
Package.swift                 Swift package with the testable logic
Sources/AaronCore             shared building blocks
Sources/AaronPreview          preview rendering
Sources/AaronAI               AI actions, suggestion protocol, review state
Sources/AaronPelican          Pelican detection and tag completion
Tests/<Module>Tests           unit tests (Swift Testing)
App/                          Xcode project (generated by XcodeGen)
  project.yml
  Sources/Aaron               SwiftUI/AppKit application layer
  Tests                       hosted app unit tests (XCTest)
  UITests                     UI tests (XCUITest) and fixture scripts
  SmokeTests                  permission-free end-to-end scenarios
docs/user                     end-user documentation
docs/developer                developer documentation
```

Dependencies only point "down": the app depends on all four libraries;
`AaronPreview`, `AaronAI` and `AaronPelican` depend on `AaronCore` and not on
each other. The only third-party dependency is Apple's
[swift-markdown](https://github.com/swiftlang/swift-markdown) (cmark-gfm),
used by the built-in renderer.

The application layer is intentionally thin: views and AppKit glue. All
logic that can be expressed without AppKit lives in the package and is unit
tested.

### AaronCore

- `CommandTemplate` — expands placeholders (`{file}`, `{dir}`, `{filename}`,
  `{stem}`, `{relpath}`, `{tmpfile}`) in a user-provided shell command,
  shell-quoting each substituted value.
- `ProcessRunner` — runs a shell command (`/bin/zsh -l -c`) asynchronously,
  feeding stdin, collecting stdout/stderr, enforcing a timeout and
  supporting cancellation. Adds common tool directories to `PATH`, since GUI
  apps do not inherit the user's shell `PATH`.
- `FrontMatter` — detects and parses a leading metadata block, either
  Pelican/MultiMarkdown style (`Key: value` lines) or YAML (`---` fenced).
- `MarkdownHighlighter` — produces style runs (heading, emphasis, code, link,
  metadata, …) for the editor's syntax highlighting.
- `TextStatistics` — word and character counts for the status bar.
- `Configuration` / `ConfigurationStore` — the Codable settings model and
  its JSON persistence.

### AaronPreview

- `PreviewRenderer` protocol: `render(PreviewRequest) async throws -> String`.
- `BuiltinMarkdownRenderer` — swift-markdown → HTML, with front matter
  stripped and shown as a small header, wrapped in a light/dark stylesheet.
- `ExternalCommandRenderer` — pipes the current buffer to a configured
  command and returns its stdout as HTML.
- `PreviewAssetResolver` — maps URLs requested by the preview page to local
  files (configurable URL prefix → directory mappings, falling back to the
  document's directory), rejecting path traversal.

### AaronAI

- `PromptBuilder` — combines the action prompt, the response-format
  instructions, an optional selection focus and the document.
- `ResponseExtractor` — finds the JSON payload in the tool output (plain,
  fenced, or wrapped by `claude --output-format json`).
- `QuoteResolver` — turns `original` + `prefix` + `suffix` quotations into
  `NSRange`s (UTF-16) deterministically; ambiguous or missing quotations are
  reported as unresolved, never guessed.
- `ReviewSession` — the review-mode state: suggestions with status
  (open, accepted, dismissed, stale, unresolved), range shifting after edits,
  and accept/dismiss operations.
- `AIActionRunner` — runs an action with its provider through
  `ProcessRunner` and produces suggestions bound to a document revision.

### AaronPelican

- `PelicanDetector` — decides whether a document is a Pelican post.
- `TagListParser` — parses the tag command's output (JSON or plain text).
- `TagCompletion` — given text and caret, finds the tag being typed on the
  `Tags:` line and ranks candidates.
- `TagProvider` — runs the tag command and caches the result.

## AI suggestion protocol

The AI never reports character offsets. It quotes:

```json
{
  "suggestions": [
    {
      "original": "virtual machine",
      "prefix": "Docker is a ",
      "suffix": " that makes deployment",
      "replacement": "containerization technology",
      "message": "Docker uses containers rather than virtual machines.",
      "category": "accuracy"
    }
  ]
}
```

`prefix`, `suffix`, `replacement` and `category` are optional; a missing or
`null` replacement makes the suggestion a comment. The editor resolves each
quotation against the exact text that was sent:

1. Find every literal occurrence of `original`.
2. Keep those whose preceding text ends with `prefix` and whose following
   text starts with `suffix`.
3. Exactly one survivor → resolved range. Otherwise, if the context matched
   nothing but `original` occurs exactly once, that occurrence is used.
   Anything else is *unresolved* and shown in the list without a highlight.

Suggestions belong to the revision they were computed for. The editor is
read-only while an action runs, so the revision cannot change underneath it.
After results arrive, every edit (accepting a suggestion or typing) is
mapped through the session: suggestions entirely after the edit shift by the
length difference, ones entirely before stay, overlapping ones become
*stale* and can no longer be accepted.

## Preview pipeline

Edits are debounced (0.25 s built-in, 0.8 s external; switching renderer
renders immediately); the selected renderer
produces HTML which is loaded into a `WKWebView` through a custom URL scheme
(`aaron-preview://`). The scheme handler serves the page itself and resolves
every other request through `PreviewAssetResolver`, so themes referencing
root-relative assets (`/articles/theme/…`) work when a mapping is
configured. Scroll position is preserved across refreshes. Links to
external sites open in the default browser.

## Configuration

A single JSON file at
`~/Library/Application Support/Aaron/config.json` (overridable with the
`AARON_CONFIG_PATH` environment variable, used by UI tests). It is edited
through the Settings window and can also be edited by hand. See the user
documentation for the format.

## Testing

- Package unit tests: `swift test` (Swift Testing), covering all package logic.
- App unit tests (`AaronTests`, hosted XCTest) for app-target logic.
- Smoke tests: `scripts/smoke-test.sh` drives the real Debug app through a
  built-in harness and checks its state; no OS permissions needed.
- UI tests (`AaronUITests`, XCUITest) drive the app through accessibility;
  they need macOS UI automation permission.
- See [development.md](development.md) and [testing.md](testing.md).
